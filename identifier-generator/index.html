        Why "not guaranteed non-real"?
        

          No public specification reserves a test-only range for these identifiers. The Digital Health Agency and Services Australia
          publish official test data to registered vendors, but it is gated and aimed at conformance testing.
          Some spaces are crowded: an 8-digit Medicare base has roughly 50 million combinations, and millions of cards are in use.
          So a valid-looking value can match a real one. The generator never emits the demo values listed in
          config/reserved.js, and it generates the strictest valid subset of each format.
        

      

      

        Use it as a library

import { generate, validate, toFhirIdentifier } from './modules/registry.js';

generate('ihi', { count: 5, seed: 42 });        // ['8003...', ...]
validate('ihi', '8003609928383098');            // { valid: true, warnings: [] }
toFhirIdentifier('ihi', '8003609928383098');    // { system, value }

        
Runs in browsers and Node (ES modules, no dependencies).
